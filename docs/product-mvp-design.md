# PeopleLens 产品 MVP 设计

## 1. 产品定义

PeopleLens 是一个面向深度阅读的人物识别与记忆助手。它把文章中出现的人物整理成一份清晰的“人物演员表”：这个人是谁、为什么出现在这篇文章里、和其他人有什么关系，以及读者之前是否见过他。

PeopleLens 不应该被定位成另一个通用 AI 摘要工具，也不应该只是百科查询插件。它的核心承诺是：

> 当你阅读人物密集的文章时，PeopleLens 帮你看懂人名背后的身份、角色、履历和关系，并在下次遇到同一个人时提醒你。

## 2. 目标用户

### 核心用户

- 经常阅读科技、商业、金融、政策、历史和长篇报道的人。
- 阅读时容易把人名、职位、派系、组织和过往事件搞混的人。
- 希望积累人物认知，但不想维护重型个人知识库的知识工作者。

### 早期用户画像

- 每周阅读 5 篇以上长文章。
- 阅读时经常打开搜索、Wikipedia、LinkedIn 或新闻资料页。
- 相比快速略读，更在意理解上下文和之后能否记住。
- 愿意点击一次插件按钮，换取可靠的人物卡片和关系梳理。

## 3. 核心任务

1. 当我在文章里遇到陌生人名时，我想不离开当前页面就知道他是谁。
2. 当一篇文章里出现很多人时，我想快速知道他们各自的角色和关系。
3. 当同一个人下次再次出现时，我想知道自己之前在哪里见过他。
4. 读完一篇人物密集的文章后，我想得到一个简洁的人物复盘。

## 4. MVP 产品原则

- 文章优先：解释人物在当前文章里的作用，而不是只给通用百科资料。
- 低打扰：阅读页面始终是主场，PeopleLens 以侧边栏和轻量卡片辅助阅读。
- 可信默认：重要判断需要展示来源、证据或置信度。
- 轻量记忆：记录有用的人物遇见历史，不记录完整浏览轨迹。
- 范围收敛：优先支持新闻、商业、科技文章里的公众人物。

## 5. MVP 范围

### 必须包含

1. Web Demo 输入
   - 支持粘贴文章正文。
   - 可选填写文章标题和来源 URL。
   - 生成“本文人物”视图。

2. 人物抽取
   - 从英文和中文文章中抽取可能的人名。
   - 合并重复提及和简单别名。
   - 按文章重要性对人物排序。

3. 人物卡片
   - 姓名。
   - 一句话身份。
   - 在本文中的角色：为什么这个人出现在这里。
   - 来自文章的关键证据句。
   - 没有可靠照片时使用首字母或占位头像。
   - 支持保存/收藏人物。

4. 本文人物侧边栏
   - 主要人物。
   - 次要人物。
   - 提及次数和相关性。
   - 快速筛选：全部、主要、已保存、不确定。

5. 人物关系摘要
   - 从文章上下文中抽取可能的人物关系。
   - 先用可读文字呈现，不急着做复杂图谱。
   - 示例：“Sam Altman 与 Elon Musk：OpenAI 早期共同创办人，后来在组织方向上产生分歧。”

6. 本地记忆
   - 在浏览器本地保存已收藏人物和历史遇见记录。
   - 同一个人再次出现时展示“之前见过”。
   - 支持清空本地数据。

7. 隐私姿态
   - 只在用户主动点击时分析。
   - MVP 不做后台网页扫描。
   - 不要求账号。
   - 不收集完整浏览历史。

### 应该包含

- Chrome Extension 原型和右侧侧边栏。
- 一键分析当前页面。
- 基础网页正文抽取。
- 将当前人物表导出为 Markdown。

### MVP 不做

- 完整个人 CRM。
- 社交功能。
- 团队知识库。
- 自动扫描所有网页。
- 联系方式、邮箱、电话、销售线索等人物情报能力。
- 复杂的全局知识图谱。
- 为每个人保证找到真实照片。

## 6. 产品形态

### 第一阶段：Chrome Extension MVP

当前优先验证入口是 Chrome Extension：

1. 用户打开真实文章。
2. 点击浏览器插件图标打开侧边栏。
3. 用户主动点击“分析当前页面”。
4. PeopleLens 使用配置的 AI 服务商生成人物卡片和关系摘要。
5. 用户保存人物，并在同一浏览器中再次看到相关提醒。

这个阶段验证核心价值：人物演员表是否真的让真实阅读流更好懂。

### 第二阶段：Web 支持面

Web 应用暂不作为公开上线目标，保留为：

- 本地开发和 AI 设置验证。
- 手动粘贴文章的调试入口。
- 隐私政策、条款和未来支持页资产。

### 第三阶段：人物记忆层

形成长期价值：

- “你上次在某篇文章里见过他。”
- “他经常和某个组织/事件一起出现。”
- “你之前可能把他和某个人搞混过。”
- 对已收藏人物生成轻量复习卡。

## 7. MVP 用户体验

### Web 支持面首屏

首屏就是工具本身，不做营销落地页，但该页面不是本阶段公开发布目标。

布局：

- 左侧：文章输入区。
- 右侧：生成的人物侧边栏。
- 下方或次级区域：关系摘要和记忆记录。

主要操作：

- 用 AI 分析文章。
- 保存人物。
- 导出 Markdown。
- 清空本地记忆。

### Chrome Extension 侧边栏

用户点击插件后：

1. 侧边栏打开。
2. 顶部显示当前页面标题和来源域名。
3. 用户点击“分析当前页面”。
4. 加载状态显示“AI 分析中”。
5. 结果以人物演员表形式出现。

建议分区：

- 本文人物。
- 主要人物。
- 次要人物。
- 人物关系。
- 之前见过。

### 人物卡片字段

每张卡片包含：

- 姓名。
- 身份：一句话职位、头衔或代表身份。
- 在本文中：一句话解释其上下文作用。
- 证据：1-2 条来自原文的句子。
- 履历：可选，3 条以内关键节点。
- 记忆：之前出现过的文章和保存状态。
- 置信度：高、中、不确定。

### 悬浮卡片行为

悬浮卡片应作为 MVP+ 功能，不要第一版就强行做自动标注，因为网页改写很容易产生噪音。

后续加入时：

- 只给高置信度人名加轻微下划线。
- 点击或悬停打开人物卡。
- 提供“在此网站禁用”。
- 避免修改输入框、编辑器、后台系统、邮箱、银行和私密文档页面。

## 8. 信息架构

### 主要视图

1. 分析页
   - 文章输入或当前页面分析。
   - 生成人物列表。

2. 人物详情
   - 展开的人物卡片。
   - 原文证据。
   - 历史遇见记录。

3. 记忆库
   - 已保存人物。
   - 最近见过的人。
   - 按姓名、组织或文章搜索。

4. 设置
   - AI Provider 或 API Key 配置。
   - 本地数据管理。

## 9. 数据对象

### Article 文章

- id
- title 标题
- url 来源链接
- domain 来源域名
- textHash 正文哈希
- createdAt 创建时间
- analyzedAt 分析时间

### Person 人物

- id
- canonicalName 标准姓名
- aliases 别名
- identity 身份
- avatarUrl 头像地址
- confidence 置信度
- sourceRefs 来源引用
- createdAt 创建时间
- updatedAt 更新时间

### Mention 提及

- id
- articleId 文章 ID
- personId 人物 ID
- surfaceText 原文出现形式
- sentence 所在句子
- startOffset 起始位置
- endOffset 结束位置
- importanceScore 重要性分数

### Relationship 关系

- id
- articleId 文章 ID
- personIds 相关人物
- relationshipLabel 关系标签
- summary 摘要
- evidenceSentenceIds 证据句 ID
- confidence 置信度

### Memory 记忆

- personId 人物 ID
- saved 是否保存
- encounters 遇见记录
- userNotes 用户笔记
- confusedWith 容易混淆的人
- lastSeenAt 最近见到时间

## 10. 排序逻辑

人物排序应使用混合评分：

- 提及频率。
- 第一次出现的位置。
- 是否出现在标题或副标题。
- 是否靠近文章主题关键词。
- 是否出现在人物关系句中。
- 姓名附近是否有明确头衔或角色。
- 用户之前是否保存或见过。

MVP 的用户可见结果由 AI 结构化分析生成，只要界面能表达证据和不确定性。

## 11. AI 行为设计

AI 应输出结构化结果，而不是一段自由散文。

必要输出字段：

- people[] 人物列表。
- relationships[] 关系列表。
- articleSummaryForContext 文章背景摘要。
- uncertaintyNotes[] 不确定性说明。

模型提示词应要求：

- 默认只使用当前文章文本，除非用户明确开启外部资料增强。
- 区分“原文事实”和“外部履历事实”。
- 不确定时标注不确定，而不是编造头衔或关系。
- 优先生成简短的上下文角色说明。
- 对非公众人物或敏感场景只做文章内解释，避免外部追踪式补全。

## 12. 信任、隐私与安全

### 公众人物边界

PeopleLens 优先增强公众人物。对于敏感场景中出现的普通人，应仅提供文章内上下文，不做外部资料补全。

### 数据最小化

- 只保存抽取出的人物、来源文章元数据和用户保存行为。
- 默认不在分析后长期保存完整文章正文。
- MVP 采用本地优先存储。

### 用户控制

- 删除全部本地记忆。
- 删除单个人物。
- 禁用某个域名的分析。
- 导出已保存数据。

### 来源透明

每张人物卡都应该标明信息来源：

- 当前文章。
- 用户记忆。
- 外部来源。
- 模型推断。

## 13. 成功指标

### 激活

- 每篇文章是否能产出至少 3 张有用人物卡。
- 从粘贴文章到第一张可用卡片的时间。

### 价值

- 每篇文章的人物保存率。
- 卡片展开率。
- 人物关系区点击或阅读率。
- 用户反馈：“这是否帮助你更好理解文章？”

### 留存

- 7 天内重复使用率。
- 再次出现的人物数量。
- 已保存人物被重新查看的次数。

### 质量

- 错误人物抽取率。
- 同名人物混淆率。
- 无来源断言比例。
- 用户删除或纠正次数。

## 14. MVP 验证计划

### 测试文章集

先准备 30 篇文章：

- 10 篇科技/商业文章。
- 10 篇政治/政策文章。
- 5 篇中文文章。
- 5 篇长篇人物报道或解释性文章。

### 人工评估

每篇文章检查：

- Top 5 人物是否正确。
- 人物角色是否足够贴合当前文章。
- 关系摘要是否有帮助。
- 是否过度增强了私人或敏感人物。
- 是否减少了用户跳出搜索的需求。

### 用户测试

找 5-8 个目标用户读同一类复杂文章：

1. 不使用 PeopleLens。
2. 使用 PeopleLens。
3. 对比理解程度、记忆程度和阅读打断感。

如果用户明确表示“它让我不再混淆人物”，并希望在真实文章上使用，MVP 就有继续投入的理由。

## 15. 路线图

### 里程碑 1：Chrome Extension MVP

- 侧边栏。
- 点击后分析当前页面。
- AI 结构化抽取人物。
- 生成人物卡。
- 本地保存人物。
- 导出 Markdown。

### 里程碑 2：Web 支持面

- 粘贴文章。
- AI 设置验证。
- 隐私和条款支持页。

### 里程碑 3：更好的身份识别

- 实体链接。
- 别名处理。
- 带引用的外部资料增强。
- 头像来源策略。

### 里程碑 4：记忆与复习

- 之前见过提醒。
- 易混淆人物。
- 已保存人物复习。
- 跨文章人物时间线。

### 里程碑 5：同步与协作

- 可选账号。
- 加密同步。
- 导入/导出。
- 阅读器集成。
